# خانهٔ ساعت

فروشگاه ساعت فارسی با رابط راست‌به‌چپ، پنل مدیریت، سبد خرید، ثبت سفارش و تجربهٔ پرو ساعت روی مچ نمونه.

نسخهٔ آنلاین: https://watch-store-nu-ten.vercel.app

## امکانات

- کاتالوگ، مجموعه‌ها و گروه‌ها با فیلتر قیمت، جستجو و صفحه‌بندی
- جزئیات محصول، انتخاب رنگ، کنترل موجودی و نمای نزدیک تصاویر
- علاقه‌مندی‌های محلی، مقایسهٔ سه ساعت و راهنمای انتخاب
- پرو ۱۲ مدل روی مچ ثابت با انتخاب تصویری و ورق‌زدن
- سبد خرید، فرم نشانی، نقشه و پیشنهاد آدرس قابل‌ویرایش
- بازه‌های تحویل با کنترل ظرفیت و اعتبارسنجی سمت سرور
- جریان پرداخت نمایشی با وضعیت موفق، ناموفق و انقضای نشست؛ بدون اتصال به شبکهٔ بانکی
- مدیریت محصولات، موجودی رنگ‌ها، سفارش‌ها و نمودارهای داشبورد
- احراز هویت ادمین با کوکی HttpOnly و تمدید access token

## فناوری‌ها

Next.js App Router، React، TypeScript، Tailwind CSS، shadcn/ui، TanStack Query، Axios، Redux Toolkit، React Hook Form، Zod، Embla Carousel، Leaflet، Tiptap و Recharts.

قرارداد API با JSON Server و Express پیاده‌سازی شده است. اجرای محلی از server/db.json و server/uploads استفاده می‌کند. در Vercel داده‌ها، نشست‌ها و فایل‌های آپلودی در PostgreSQL ذخیره می‌شوند.

## اجرای محلی

پیش‌نیاز: Node.js 22 یا جدیدتر و npm.

```bash
npm ci
npm ci --prefix server
```

از `.env.example` یک فایل `.env.local` بسازید:

```dotenv
NEXT_PUBLIC_API_BASE_URL=http://localhost:3002
```

از `server/.env.example` یک فایل `server/.env` بسازید. برای `AUTH_JWT_SECRET` و `AUTH_REFRESH_SECRET` دو مقدار تصادفی متفاوت تنظیم کنید؛ این فایل‌ها را کامیت نکنید. اطلاعات ورود از رکورد ادمین دیتابیس خوانده می‌شود؛ رمز حساب را پیش از استفادهٔ عمومی تغییر دهید.

در دو ترمینال جدا اجرا کنید:

```bash
npm run backend
```

```bash
npm run dev
```

فروشگاه: `http://localhost:3000` — ورود مدیریت: `http://localhost:3000/admin/login`.

## کنترل کیفیت و ساخت

```bash
npm run lint
npm run build
npm run start
```

سرور API باید هنگام استفاده از صفحات متصل به داده در دسترس باشد. `npm run start` فقط برنامهٔ Next.js را اجرا می‌کند.

## تصاویر محصولات و پرو

هر محصول تصویر اصلی اختصاصی دارد. شناسهٔ محصولات ثابت می‌ماند تا لینک‌ها و سفارش‌های تاریخی تغییر نکنند. اطلاعات نام، قیمت و رنگ سفارش‌ها به‌صورت snapshot نگهداری می‌شود.

تصاویر پرو در `public/images/try-on/watches` قرار دارند. اتصال نام فایل به شناسهٔ محصول و محل قرارگیری روی مچ در `src/config/try-on.json` تنظیم می‌شود. نام ترتیبی عکس، به‌تنهایی شناسهٔ محصول نیست. محدودهٔ پیکسل‌های قابل‌مشاهده برای تصاویر جدید باید تنظیم شود تا حاشیهٔ شفاف باعث اختلاف اندازه نشود.

پرو از تصویر دست ثابت و ماسک استفاده می‌کند؛ نیاز به دوربین ندارد و اندازهٔ واقعی ساعت روی دست کاربر را محاسبه نمی‌کند.

## استقرار روی Vercel

فروشگاه و API در یک پروژهٔ Next.js مستقر می‌شوند. مسیرهای API در `next.config.ts` به تابع `/api/backend/[...path]` بازنویسی می‌شوند؛ کوکی‌های ورود روی دامنهٔ فروشگاه باقی می‌مانند.

1. پروژه را به Vercel متصل کنید و از Marketplace دیتابیس Neon بسازید. اتصال باید `DATABASE_URL` را در محیط Production تنظیم کند.
2. `NEXT_PUBLIC_API_BASE_URL` و `STORE_ORIGIN` را برابر آدرس HTTPS فروشگاه، بدون اسلش پایانی، قرار دهید.
3. برای `AUTH_JWT_SECRET` و `AUTH_REFRESH_SECRET` دو مقدار تصادفی متفاوت و خصوصی تنظیم کنید.
4. برای اولین استقرار، رمز جدید ادمین را در متغیر خصوصی `CLOUD_ADMIN_PASSWORD` قرار دهید. اسکریپت راه‌اندازی آن را با scrypt و salt مستقل هش می‌کند؛ رمز محلی به نسخهٔ عمومی منتقل نمی‌شود.
5. `vercel --prod` را اجرا کنید. فرمان ساخت در `vercel.json` ابتدا جدول‌ها و دادهٔ اولیه را ایجاد می‌کند، سپس Next.js را می‌سازد. اجرای مجدد، دیتابیس آنلاین را بازنویسی نمی‌کند.
6. پس از راه‌اندازی موفق، `CLOUD_ADMIN_PASSWORD` را از محیط Vercel حذف کنید؛ ورود از هش ذخیره‌شده استفاده می‌کند. بازنشانی رمز با به‌روزرسانی هش و salt و لغو نشست‌ها انجام می‌شود، نه تغییر دادهٔ seed.

### روش ذخیره‌سازی

`server/cloud-handler.js` برای هر درخواست تراکنش باز می‌کند و سطر `store_state` را با `SELECT ... FOR UPDATE` قفل می‌کند. مسیرهای موجود روی یک snapshot حافظه‌ای کار می‌کنند؛ سپس داده‌ها و نشست‌ها پیش از ارسال پاسخ در همان تراکنش ثبت می‌شوند. خطای ذخیره، پاسخ موفق تولید نمی‌کند. به این ترتیب نمونه‌های مختلف سرور نمی‌توانند یک موجودی یا بازهٔ تحویل را هم‌زمان بفروشند.

این طراحی برای حجم این پروژه انتخاب شده و درخواست‌ها را سری می‌کند. برای ترافیک بالا باید محصولات، سفارش‌ها، نشست‌ها و ظرفیت به جدول‌های مستقل و قفل‌های ریزتر منتقل شوند. تصاویر JPEG آپلودی، با محدودیت حجم مشترک فرم و سرور، به‌صورت bytea در جدول `store_files` نگهداری می‌شوند؛ با رشد تعداد فایل‌ها، object storage مناسب‌تر است.

در ابر هیچ سفارش یا نشست جدیدی به دیسک محلی یا `/tmp` وابسته نیست. تصاویر ثابت همراه پروژه منتشر می‌شوند. فایل‌های `.env` و نسخه‌های پشتیبان نباید کامیت شوند یا در `public` قرار بگیرند. محیط Preview باید دیتابیس مستقل داشته باشد.

پرداخت پروژه به بانک متصل نیست و برداشت وجه انجام نمی‌دهد. برای پرداخت واقعی، ایجاد تراکنش و تأیید مبلغ باید در سرور با API رسمی ارائه‌دهندهٔ پرداخت جایگزین شود.
